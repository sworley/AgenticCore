# Tooling Contract

**Status:** stable contract  
**Scope:** what any agent runtime must honor to be a supported AgenticCore adapter.

AgenticCore is **tool-agnostic**. The harness provides roles, process gates, a
bench model, a task queue, documentation, and MCP services. An agent runtime
(opencode, codex, ...) is a thin, regenerable **adapter** generated from the
canonical source — not the thing the harness depends on.

## What the harness owns (tool-neutral)

| Surface | Location | Note |
|---|---|---|
| Lead-engineer persona | repo-root `AGENT.md` | session-open/close checklists, standing rules |
| Process / governance | `PROCESS.md`, `.core/invariants.md` | HIL gates, no self-approval, roles |
| Task queue | `tasks.yaml` | `.01` is the sole writer |
| Bench model | `mddocs/onboarding/bench-model.md` | `.00` HIL, `.01` lead-engineer, `.02`+ workers |
| Canonical agents | `.agents/*.md` + `.agents/_meta.yaml` | bodies are tool-agnostic; frontmatter is per-tool |
| Documentation / MCP | `mddocs/`, `mddocs/mcp/`, `mcp/` | docs via mdBook; services via MCP |
| Security policy | `.agents/_security-policy.md` | injected into AGENT.md + commit-push gate |

## What a runtime adapter must honor

To be a supported adapter, a runtime must:

1. **Read the lead-engineer persona / process.** Surface `AGENT.md`,
   `PROCESS.md`, and `.core/invariants.md` as session context.
2. **Load the agent roster.** Generate its agent definitions from the canonical
   `.agents/*.md` bodies + `.agents/_meta.yaml` frontmatter (per-tool keys).
3. **Register the MCP servers.** Provide the same services any runtime can use:

   ```sh
   uv run mcp/review-ledger/server.py --data-path .core/review-ledger/security --id-prefix SF --run-prefix SR
   uv run mcp/review-ledger/server.py --data-path .core/review-ledger/reviews  --id-prefix RF --run-prefix RR
   uv run mddocs/mcp/mcp-rag-docs/server.py --docs-root mddocs
   ```

4. **Honor the permission surface.** Translate the security policy
   (`_security-policy.md`, `PROCESS.md`) into the runtime's permission model:
   no destructive git without confirmation, deny unvetted package installs,
   restrict `webfetch`/`websearch`, and keep `approve_finding_update` at the HIL
   plane (hil-assistant) only.
5. **Respect the bench namespace.** The `.01` directory is the management plane;
   `.00` is the HIL worktree (never torn down); `.02`+ are workers. The agent
   operates as `lead-engineer` in `.01` and never writes into `.00`/`.02+` files
   directly via MCP.

## Adapter anatomy

```
opencode adapter    opencode.json + .opencode/agents/*  (generated by sync-agents.sh)
                    start-opencode.sh                  (cd into project root; isolates cwd)
codex adapter       .codex/ + start-codex.sh           (generated by tool-adapter.sh)
<other> adapter     <runtime-config>                   (generate from .agents/_meta.yaml)
```

- The **canonical source** is `.agents/` and `mddocs/mcp/` + `mcp/` — stable.
- The **adapter** is a small, regenerable translation layer — fast-moving.
- **Never** put harness/process logic in an adapter; adapters only emit config.
- Each adapter ships a `start-<tool>.sh` that `cd`s into the project root, so the
  runtime loads that directory's local config while still allowing your global
  config to apply.

## Adding a new runtime

1. Add per-tool frontmatter keys under each agent in `.agents/_meta.yaml`.
2. Write a generator (or extend `tool-adapter.sh`) that emits that runtime's
   config from `.agents/` + the MCP/policy sources.
3. Register it as a `--tool` value in `adopt.sh` and `tool-adapter.sh`.
4. Document it here.

Design rule: if you must change the **harness** to support a tool, the contract
is leaking — push that concern into the adapter instead.

See also: `mddocs/onboarding/bench-model.md`,
`mddocs/operations/runbooks/configure-agents.md`.
