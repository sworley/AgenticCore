# ADR-0012: Bench Assignment — Canonical/Generated Split

**Date:** 2026-06-29
**Status:** Accepted
**Supersedes:** —
**Superseded by:** —

## Context

Every bench merge was clobbering the lead-engineer AGENT.md in the `.01` namespace.
The root cause: `provision-bench.sh` was instructing the operator to copy
`bench-AGENT.md.pattern-a` to the bench worktree as `AGENT.md`, and that file was
then committed to the bench's feature branch. When the branch was merged, the AGENT.md
at the repo root was overwritten with the bench-scoped version.

This violates two prior decisions:

- **ADR-0001 (Decision 5 — Agent Definition Propagation):** Tool-specific outputs are
  generated from canonical sources; they must not be hand-edited or committed as
  first-class artifacts.
- **ADR-0009 (D-3 — `_meta.yaml` Projection Pattern):** The extension point for adding
  a new AI tool is the generator (`sync-agents.sh`), not committed per-tool files on
  feature branches.

The architecture conflates two distinct concerns:

1. **What a bench is doing** — tool-agnostic; belongs in version control
2. **How a tool is instructed** — tool-specific; belongs only on disk at provision time

---

## Decision

Introduce `.bench/assignment.md` as the **canonical, tool-agnostic, committed** bench
record. Tool-specific files (`AGENT.md` for AI toolchain; future equivalents for other
tools) are **generated at provision time** by `provision-bench.sh` and excluded from git.
They are never committed to bench branches.

`provision-bench.sh` now:
1. Creates `.bench/assignment.md` with TICKET, BRANCH, PATTERN, and TASK fields and
   commits it to the bench branch.
2. Generates `AGENT.md` in the bench worktree root by substituting the four fields
   into the pattern template.
3. Adds `AGENT.md` to the bench worktree's local git exclude (`.git/info/exclude`),
   preventing accidental staging.

---

## Consequences

**Positive:**
- Bench merges no longer conflict on `AGENT.md`. The file does not exist in git on
  bench branches, so there is nothing to clobber.
- Adding support for a new AI tool requires only a new generator block in
  `provision-bench.sh` — the same extension point pattern as `sync-agents.sh` for agent
  definitions (ADR-0001, Decision 5).
- `.bench/assignment.md` is human-readable and tool-independent. Any operator or tool
  can discover what a bench is working on without knowing the AI toolchain filesystem
  cascade or any other tool-specific mechanism.
- Consistent with ADR-0009 D-5: bench identity is now discoverable from the filesystem
  by any tool.

**Negative / Trade-offs:**
- `AGENT.md` must be regenerated if a bench worktree is destroyed and rebuilt. The
  canonical record (`.bench/assignment.md`) survives; the tool-specific file does not.
- Operators who inspect a bench directory by hand will not find a `AGENT.md` in git
  history — only on disk. This is intentional but may be surprising.

**Neutral:**
- The pattern template files (`.agents/bootstrap/bench-AGENT.md.pattern-a`, etc.)
  remain as the authoritative source for tool-specific framing. Their header comment
  now reads `# Generated by provision-bench.sh — do not commit` to make their role
  explicit.

## Amendment (2026-08-20, TC-056): `.bench/assignment.md` is no longer committed

**Status of this decision:** Amendment. Supersedes the "commit it" clause of the
original Decision above. The original Decision's tool-agnostic/tool-specific split
(`.bench/assignment.md` vs. `AGENT.md`) remains valid and is **not** reversed by this
amendment — only the "committed" half of that split is reversed.

**What is superseded.** The original Decision states: "Introduce `.bench/assignment.md`
as the **canonical, tool-agnostic, committed** bench record." The "committed" clause is
superseded. `.bench/assignment.md` is now gitignored, disk-local, and regenerable. It is
written to disk by `provision-bench.sh` exactly as before, but it is never staged or
committed to the bench branch.

**Why.** `bench-registry.yaml` is confirmed as the canonical, durable, queryable
per-bench provenance record — and it is richer than `assignment.md` was: it carries
lifecycle state, teardown status, merge refs, and findings, none of which
`assignment.md` ever captured. With `bench-registry.yaml` filling that role, a committed
`assignment.md` on every bench branch is redundant noise on shared branches.
Empirically: inspection of `main`/`dev` showed clobbered, mismatched `assignment.md`
content across historical bench merges, with zero audit value recovered from any of it.

**The coherent rule.** This amendment is an instance of a general rule, stated here for
reuse in future decisions of this shape:

> Anything whose value is scoped to "what is happening in this specific live worktree
> right now" is gitignored; anything that must persist as durable, queryable history
> goes in a registry file (`bench-registry.yaml` for benches, `tasks.yaml` for tickets).

**What is preserved.** The attendant and other bench-local tooling still read
`.bench/assignment.md` **on disk, inside their own live worktree**. That read-path
dependency is unchanged — the file exists at the same path with the same content
immediately after provisioning. Only its git-tracked status changes.

**TC-021 regression check.** `.bench/` was briefly gitignored once before (TC-021) and
that change was reverted because the ignore rule silently blocked `provision-bench.sh`'s
`git add .bench/assignment.md` step, leaving the script in a broken partial state. This
amendment does not reintroduce that failure mode: `provision-bench.sh`'s `git add` and
`git commit` steps for `.bench/assignment.md` are **removed as part of this same
change**, so there is no add/commit step left for the ignore rule to silently block.
The `mkdir -p` and heredoc write to disk are unchanged.

**Implementation.**
- `.gitignore`: `.bench/` added, alongside `.worktrees/` and `worktrees/` as
  worktree-local ignores.
- `mddocs/scripts/provision-bench.sh`: `git add .bench/assignment.md` and the
  corresponding `git commit` removed; file-write step unchanged.
- This bench's existing on-disk `.bench/assignment.md` files are untracked via
  `git rm --cached` (disk copy preserved) rather than deleted, per bench, as each
  bench next touches the file.

**Related:** TC-056, TC-021 (original ignore/commit collision), ADR-0015 D-6/D-7
(addendum-style ADR evolution pattern followed here).
