# Release v0.6.0

**Date:** 2026-11-08
**Tag:** `v0.6.0`
**Branch:** `release/v0.6.0`
**Previous release:** v0.5.0

## Summary

v0.6.0 is the first release under the formalized release/baseline process. It carries two
themes: (1) the **adoption toolchain** — making onboarding reliable and self-contained for
a real adopter via a project-local Python environment and a generic toolchain manager; and
(2) the **formalized framework release process** — resolving the baseline-steward
(owner/gate) vs release-engineer (tactical executor) split and establishing release
scaffolding on the v0.5.0 baseline.

**Changes since v0.5.0:**

- **Adoption toolchain**
  - Project-local Python environment (`python-env.sh`) — `adopt.sh` provisions
    `<project>/.venv`, installs pinned deps (`mcp`, `pyyaml`, `fastmcp`), validates imports
  - Generic toolchain manager (`toolchain.sh`) — validates/installs mdBook, mdbook-mermaid,
    typos-cli, shellcheck, gh, jq (`--check` / `--install`)
  - mdBook 0.5.3 standardization — docs build pinned to a known-good version
  - `.envrc` hardened — always rebuilt from `.envrc.template`; venv sourced on `cd`
  - `check-env.sh` — validates the project-local venv + Python deps
- **Formalized release process**
  - Role split resolved — `baseline-steward` = framework release owner/gate;
    `release-engineer` = tactical executor
  - `release-process.md` re-attributed + Scope & Ownership + operational notes
  - Release scaffolding — `UNRELEASED.md` running draft; CHANGELOG/README baseline
  - `AC-0002` / `AC-0003` tracking
- **Docs & governance**
  - `CONTRIBUTING.md` — "Two Ways to Contribute"
  - Onboarding/visual overviews — release-engineer tasking clarified
  - Worked example aligned to the v0.6.0 flow
- **Infra**
  - `requirements.txt` pinned for the project-local venv
  - CI `verify` workflow updated for the adopted toolchain

## What Changed

### New Capabilities
- **Project-local Python environment (`python-env.sh`)** — `adopt.sh` now provisions
  `<project>/.venv`, installs the pinned Python deps (`mcp`, `pyyaml`, `fastmcp`), and
  validates imports; builds `.envrc` from `.envrc.template` so the venv sources on `cd`
  via direnv `layout python`.
- **Generic toolchain manager (`toolchain.sh`)** — `--check` (validate) / `--install`
  (opt-in) for the docs/dev toolchain: mdBook, mdbook-mermaid, typos-cli, shellcheck, gh, jq.
- **mdBook 0.5.3 standardization** — docs build pinned to a known-good mdBook.

### Improvements
- **Formalized release process** — `baseline-steward` = framework release owner/gate;
  `release-engineer` = tactical executor (`HIL → baseline-steward → release-engineer`);
  `release-process.md` re-attributed; adopter-impact and operational notes added.
- **Release scaffolding** — `UNRELEASED.md` is the running draft anchored at v0.5.0;
  CHANGELOG/README mark the baseline and the next release.
- **Contribution clarity** — `CONTRIBUTING.md` documents the two contribution paths:
  direct-repo PR vs severed-adopter Pattern Promotion.
- **Adoption UX** — `adopt.sh` added a dry-run and a toolchain-install decision point.

### Fixes
- `.envrc` is always rebuilt from `.envrc.template` (no stale/divergent state).
- `.venv` is sourced explicitly via direnv `layout python`.

### Infrastructure / Pipeline
- `requirements.txt` pinned for the project-local venv (MCP, pyyaml, fastmcp).
- CI `verify` workflow updated for the adopted toolchain.
