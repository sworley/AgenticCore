# Examples

Worked examples showing the framework in motion. These are illustrative — they
demonstrate real patterns against realistic scenarios without being prescriptive.

Use these as a starting point. Adapt to your project's context.

## Examples

| Example | What It Shows |
|---|---|
| [Ticket Lifecycle](ticket-lifecycle.md) | A task from backlog entry to merged — full status transitions, bench provisioning, relay, and HIL acceptance |
| [Bench Session Walkthrough](bench-session-walkthrough.md) | A complete agent session on a worker bench — open, do work, close |
| [ADR Decision Process](adr-decision-process.md) | Writing an ADR from a real decision — context, options, decision, consequences |
| [Release Process](release-process.md) | Cutting v1.0.0 — all eight HIL gates, security review, release notes, tag, and branch |

## How to Read These

Each example follows the same structure:

- **Scenario** — the concrete situation being illustrated
- **What happens** — the sequence of actions, commands, and state changes
- **Key points** — what to take away

Nothing here is normative. If your project does it differently and it works, that's fine.
The reference architecture (`mddocs/reference.architecture/`) is where the prescriptive
patterns live.
