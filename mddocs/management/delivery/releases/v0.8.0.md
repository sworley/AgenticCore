# Release v0.8.0

**Date:** 2026-11-24
**Tag:** `v0.8.0`
**Branch:** `release/v0.8.0`
**Previous release:** v0.7.0

## Summary

v0.8.0 completes the documentation/knowledge taxonomy adoption and introduces a
metadata-driven shipping contract. The framework adopts the management-plane
taxonomy (ADR-0029), the classification-ID and frontmatter metadata contracts
(ADR-0032) with machine-checked conformance, makes the
`allowed_in_adopter_repos` flag the authoritative, fail-closed shipping gate
(ADR-0015 D-9, AC-0014), adopts reusable management tooling (AC-0015),
establishes the ADR forward-only supersede convention (ADR-0035), and adopts
GitHub branch-protection rulesets for `main`/`dev` (ADR-0036). It also ships
harness hygiene: environment-specific configuration and topology examples were
generalized to portable, deployer-neutral placeholders so the harness stays
framework-owned rather than bound to a single operator's environment, and the
`.tmp` scratch convention is documented. Adopters re-exporting across this release must note the single
adopter-Required change (AC-0014) described in the Adopter Impact section.

## What Changed

### New Capabilities

- **Project-context plane (CTX)**: ADR-0031 establishes the `Projects/<context>`
  plane and `CTX-` identifiers, and ADR-0033 adds the HIL-directed Project Context
  Adoption runbook (Q5 seeding of an existing project's docs).
- **Management tooling home**: reusable tooling under `mddocs/management/tooling/`
  (AC-0015) - mdBook validation/build helpers, rendering assets, and the
  project-protection schema. Harness-coupled tooling that depends on project
  `pyproject.toml`/locks absent from this framework was formally rejected and
  withdrawn (ADR-0032).
- **Classification-ID metadata contract** (ADR-0032) plus the
  `reconcile-metadata-registry.py` conformance tool (SH-0028) that asserts the
  SH/classification registries match artifact metadata.

### Improvements

- **Documentation/knowledge taxonomy adoption** (ADR-0029): the `mddocs/` tree is
  reorganized into planned homes (management, projects), and ADRs/runbooks are
  re-homed; metadata-conformance gates hardened (V2/V3 to blocking).
- **ADR forward-only supersede convention** (ADR-0035): accepted ADR text is never
  edited in place; a change produces a new superseding ADR, tracked by a
  machine-checked supersession ledger.
- **`.tmp` scratch convention** seeded for adopters; temp files use
  `${TMPDIR:-/tmp}`.

### Fixes

- **AC-0014 - fail-closed shipping gate**: `allowed_in_adopter_repos` is now the
  authoritative gate (ADR-0015 D-9). The gate no longer relies on matching a
  `false` literal; a missing/malformed/non-`true` value is excluded. Closes the
  fail-open gap (W1), honors `.md` script-doc frontmatter (W2), and reconciles
  stale doc frontmatter (W3). The one-shot bootstrap tools `setup/adopt.sh` and
  `export-framework.sh` (and their docs) no longer ship to adopters.
- **Portable, deployer-neutral configuration**: environment-specific identifiers
  and topology examples were replaced with portable placeholders
  (`<github-owner>`, `<owner>`, `<OWNER_ID>`) and a generic cluster description,
  consistent with the harness's deployer-neutral design.
- **ADR-0036 scope correction** (AC-0017 defect repair): corrected to the
  two-ruleset scope.
- **`bench-status.sh --stale`** uses the harness `.venv` Python (was missing
  pyyaml) and fixes a latent `tasks.yaml` unwrap crash.

### Infrastructure / Pipeline

- **GitHub branch-protection rulesets** (ADR-0036): `main-strict` and `dev-strict`
  rulesets replace the legacy branch protection; supersedes ADR-0004 (second
  forward-only supersede recorded in the ledger).

### Migration Notes

Adopters on v0.7.0 re-exporting against v0.8.0: the adoption-bootstrap artifacts
no longer ship. `mddocs/scripts/setup/adopt.sh` (plus its `.meta.yaml` and
`adopt.md` documentation) and `mddocs/scripts/export-framework.sh` (plus its
`.meta.yaml`) are excluded from the adopted tree. The export surface is now
governed entirely by the `allowed_in_adopter_repos: true` metadata contract
(ADR-0015 D-9, fail-closed). Adopters upgrade by re-running `export-framework.sh`
against the v0.8.0 tag into a new working copy, then reconciling the delta against
their customizations (ADR-0015). Framework baselines are severed and versioned
(`framework-version.txt`); there is no in-place retrofit of an already-adopted tree.
No other breaking change; otherwise a drop-in upgrade.

## Known Limitations

- The `export-framework.sh` severance test harness is sensitive to
  environment-specific git-remote fixtures; it may report its pre-existing
  remote/dirty-tree cases as failures outside a CI runner. Not release-blocking
  (CI `verify` passes on the merge; the harness passes 39/39 in a clean run).
- ADR-0030 and ADR-0034 remain as unedited superseded bodies; the ADR-0035
  retire-and-remove gate and the pre-convention amendment consolidation pass are
  deferred to a later release.
- The `Projects/<context>` plane is scaffolded but has no real context adopted
  yet (`Current contexts` is `none`). A real context import uses the ADR-0033
  runbook.
- Automated validation covers the adoption-surface and severance machinery
  (Flow A/B, rehome, target handling). The cross-version adopter "upgrade plus
  reconcile" path is a manual, adopter-scheduled process by design (ADR-0015)
  and is not exercised by an automated harness.

## Upgrade Notes

Upgrade model: re-export into a fresh working copy and reconcile the delta
(adopter-reconciliation.md). For v0.7.0 to v0.8.0, AC-0014 is the only Required
reconciliation item (see Migration Notes). Adopters coming from v0.6.0 should
also apply the v0.7.0 and v0.6.0 impact notes in order.
